# ADR 0004：客户端密钥默认放行全部车道，只能显式拒绝

- 状态：已采纳（W3 实现并验收）
- 依据：`docs/token-spec-v1.md` §3.2、`docs/design-v1.md` §9

## 背景

旧两代网关都有"白名单"机制：路由层的 `supported_models` 与厂商层的 `model_limits`。
两者的共同坑是**默认拒绝**——忘了把新模型加进白名单，故障恰好发生在新模型上线的那一刻，
表现为 400/403，排查方向完全错。

## 决策

客户端密钥默认 `lane_policy.mode = "all"`（允许全部车道），拒绝必须**显式**写入
`deny_lanes`。判定对象是**规范化后的路由键**（成员别名点名先归一到所属车道）。
命中拒绝返回 `403 forbidden_scope`，而不是 400——便于调用方区分"权限"与"请求不合法"。

## 后果

- 优点：新模型上线不需要同步改密钥配置；"忘了配"只会导致"能用"，不会导致"故障时不可用"。
- 代价：分账不再靠白名单。分账由 `KeyID` 身份承载（日志与统计按 key 聚合），
  这本来就是分账的正确做法。
- 新实例：新建客户端密钥默认置 `all`；需要收窄范围时由管理 API 显式配置 `allow_lanes` 或 `deny_lanes`。
