# ADR 0003：成员亲和默认 0（相对上游的 300 秒）

- 状态：已采纳（W2 实现并验收）
- 依据：`docs/design-v1.md` §7.3、`docs/routing-spec-v1.md` §6

## 背景

上游路由层的六键默认值是 `2 / 3 / 120 / 30 / 60 / 300`，其中亲和 300 秒用于
"多用户共享车道时压低抖动"：切换成功后粘住当前成员，避免抖动。

## 决策

PBR 的 `member_affinity_seconds` 默认改为 **0**（不做粘滞），需要时按车道显式配置。

## 理由

- 这是**单用户自用**网关，不存在多用户互相踩踏导致的抖动放大。
- 亲和会让"高优先级成员恢复后仍被低优先级成员粘住"，直接掩盖 `priority` 的语义——
  用户看到的排序与实际生效的排序不一致。
- 亲和与"熔断半开复通后应立刻回到高优先级成员"的预期相冲突。

## 后果

- 默认行为变成"每次请求都从优先级最高的可用成员开始"，可预测。
- 如果某个上游抖动明显，按车道配 `member_affinity_seconds` 即可，六键本来就支持车道级覆盖。
