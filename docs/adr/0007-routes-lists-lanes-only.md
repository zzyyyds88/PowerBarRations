# ADR 0007：路由页只列出真实车道，渠道声明与车道彻底分列

- 状态：已采纳
- 依据：`docs/design-v1.md` §6/§7.7、`docs/ui-spec-v1.md` §6.2/§6.3
- 修订：[ADR 0006](0006-lane-free-member-composition.md) 中"未配车道的路由键也以卡片出现"的展示口径；不改变 ADR 0005/0006 的路由语义

## 背景

ADR 0006 把成员候选放开到"任意启用渠道的任意已声明模型"，这是对的，保留。但它同时沿用了
一条展示口径：`/routes` 页把 `source: unconfigured`（渠道声明了、但没有同名车道）的路由键
也渲染成卡片，提示"未配车道不可调用"。

实机使用中这条口径产生两个问题：

1. **删车道后卡片仍在**。卡片由渠道 `models` 派生，与车道是否存在无关：删掉车道只是把卡片
   从"可调用"打回"未配车道"，卡片本身不会消失。用户会认为"删除车道没生效"。
2. **渠道声明与车道两个概念在同一页混杂**。产品要求是"车道和渠道管理添加的模型完全分开"：
   路由页应当只回答"有哪些车道、成员顺序是什么"，而不是顺带罗列渠道声明。

## 决策

- **`/routes` 页只列出真实车道**：渲染 `GET /api/models` 中 `source ∈ {explicit, disabled}`
  的项。`source: unconfigured` 的路由键**不再出现在路由页**。
- **新建车道一律手工输入路由键**：入口是页头「新建车道」（以及未配车道占位卡不存在后的
  唯一入口），路由键可任意命名，**无需任何渠道声明过它**（ADR 0006 的候选范围不受影响）。
- **渠道声明与车道彻底分列**：渠道 `models` 的增删只改声明，既不创建车道，也不在路由页
  产生任何卡片。"某模型当前不可调用"这一事实由**模型管理页**的「不可调用」徽章表达。
- **后端 `GET /api/models` 契约不变**：仍返回 `unconfigured` 项——模型管理页、试打台、
  `GET /v1/models` 等消费方仍需要它；只是 `/routes` 页不再渲染这些项。

## 后果

- 优点：路由页语义单一——"这里就是车道清单"；删车道 = 卡片消失，符合直觉。
- 优点：渠道声明与车道彻底解耦，"渠道新增模型后路由页冒出一张卡"的困惑消失。
- 代价：渠道声明了一个模型但还没建车道时，路由页看不到它；可发现性由模型管理页的
  「不可调用」徽章与页头「新建车道」承担。
- 不变：车道仍是唯一路由入口；没有车道一律 `503`；声明模型绝不自动建车道（ADR 0005/0006）。
