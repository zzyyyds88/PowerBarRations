# ADR 0002：成员耗尽快抛 503，不轮询等待

- 状态：已采纳（W1 实现、W2 强化）
- 依据：`docs/routing-spec-v1.md` §4.2、§10 差异清单

## 背景

旧路由层在"没有可用成员"时是**等待并轮询重试**。上游故障时，请求会悬挂到客户端自己超时；
对下游 harness 而言，远端故障表现为本地卡死，无法分类也无法快速降级。

## 决策

尝试预算用尽或无可选成员 → **立即**返回

```json
{ "error": { "message": "No available channel for model <X>" } }
```

body 形态固定（不加请求 id 后缀、不走通用错误序列化），因为下游的 fallback 分类依赖它。
快抛前必须已把本次所有尝试写入日志（含冷却/熔断状态），便于事后定位。

## 后果

- 优点：上游故障在下游表现为一个可分类的 503，而不是超时；故障定位靠日志而不是靠等。
- 代价：PBR 的 503 与旧网关的"最终超时"语义不同，切换期间需让下游按 503 分类；
  这也意味着下游的重试预算不会被 PBR 悄悄吃掉。
- 实现上的坑（已修）：转发循环的轮数上界必须比"真实尝试数"多一轮，
  否则最后一次失败会把上游的原始 500 直接透给下游，而不是契约要求的 503。
