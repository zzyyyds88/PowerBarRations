# ADR 0014: 请求资源租约与不可变路由快照

- 状态：已接受（2026-11-26）
- 关联：[ADR 0009](0009-member-groups.md)、[ADR 0012](0012-outbound-admission-control.md)、[ADR 0013](0013-error-semantics-and-display-code.md)、[routing-spec §1.3/§3/§5/§8](../routing-spec-v1.md)、[api-spec §4/§6](../api-spec-v1.md)

## 背景

请求从进入模型面到流式收尾，会跨越选路、客户端密钥鉴权、出站准入、上游转发、运行态记账与后台清理等多个生命周期。现有实现把这些资源的所有权散落在 handler、路由运行态和转发管道中，产生了以下结构性问题：

- 成员与准入运行态使用裸字符串拼接键，键的构成、作用域与生命周期没有类型约束；
- 恢复探测只记录一个成员 ID，无法证明“谁持有、属于哪一代、何时到期”，成功/失败记账会顺带释放探测位，重复收尾或迟到回调可能释放别人的租约；
- 请求结束、客户端取消、超时、panic 与流式写失败走不同出口，资源清理既可能遗漏，也可能重复执行；
- 配置迁移、状态 Prune 与人工 Reset 可能把仍在飞请求持有的探测所有权迁移、清除或复用，导致旧请求修改新状态；
- 一次请求在重试循环中反复读取配置，鉴权策略、成员渠道快照与准入快照可能来自不同版本；
- 配置 getter 会静默清掉解析失败的值，使“配置错误”被伪装成“未配置”，请求路径也可能带着不完整配置继续；
- 出站准入只区分是否拿到槽位，没有把成功、失败、中立与取消交给运行态，迟到 waiter 与配置失效仍可能重新入队；
- 流式心跳、首包、正文写出与客户端断开没有统一的终止监督，后台任务则可能持有可变配置指针或无界 goroutine。

这些问题不是单个函数的补丁可以闭合的，需要在请求边界建立明确的所有权与收口合同。

## 决策

### 1. 类型化运行态键

- 以 `MemberKey` 表示成员运行态身份，包含渠道、上游模型与成员条目身份；车道身份由 Registry 的 lane key 承载。同车道内重复的 `(渠道, 所选模型)` 仍是不同 `MemberKey`。
- 以 `AdmissionKey` 表示出站准入身份，作用域保持 ADR 0012 的渠道 × 成员所选模型；它不借用 `MemberKey` 的字符串形式。
- 两种键都是值类型，构造、比较与日志投影由 `internal/route` 统一提供；禁止调用方自行拼接字符串作为运行态键。

### 2. ProbeLease 是探测所有权的唯一凭证

- `ProbeLease` 至少包含 `owner`、`generation`、`expires_at`。`owner` 是本次请求/尝试的唯一标识，`generation` 是车道运行态代次，`expires_at` 是租约上界。
- 获取、释放与到期回收都必须同时匹配 owner 与 generation；旧 owner 的迟到 `finish/close` 不得释放新租约。
- 到期只表示租约失效并允许 State 按 generation 回收，不表示任何 goroutine 可以自行改写运行态。回收仍由 State 的单一收口路径执行。
- `Runtime.recordSuccess` 与 `Runtime.recordFailure` 只记账，**不隐式释放 probe**。释放只能由租约 owner 在请求 State 的统一收口中完成，或由 State 的到期回收完成。
- 人工探活与渠道测试不占出站准入槽位、不计 RPM；它们使用 generation 做清理前校验，不接管业务请求的 live lease。

### 3. State 的 finish/close 幂等收口

- 每个请求创建一个 State，统一持有 probe lease、准入 waiter/槽位、客户端密钥 lease、流式监督与后台任务引用。
- `finish` 与 `close` 都只执行一次有效的资源收口；重复调用、defer 与取消回调并发到达时，后续调用无副作用。
- 资源一旦创建就向 State 注册，禁止等到“可能成功”的路径才注册清理。转发管道入口即完成首次注册，后续 adapter 只补充资源，不另起清理体系。

### 4. 运行态迁移、Prune 与 Reset 不转移 live lease

- 配置迁移只迁移持久运行态，**不转移任何 live ProbeLease**；无法证明归属的旧状态宁可丢弃，也不能挂到新成员键上。
- `Prune` 只清理已失效、已到期或已无 live owner 的状态；存在 live lease 的条目必须保留。
- `Reset` 递增车道 `generation`，使全部旧 lease 立即失效，并返回被失效的 lease 数。Reset 不等待、不取消在飞请求；在飞请求仍可结束，但其运行态写入与 lease 释放必须通过 generation 校验，不能污染新状态。

### 5. Health 是只读投影

- `GET /api/lanes/{name}/health` 与 SSE 快照只读取不可变投影，不修复租约、不清理过期状态、不重置 generation、不触发上游请求。
- 过期 lease 的回收由后台 State 维护路径或下一次合法写操作完成，不能由 GET/SSE 触发。

### 6. PBRServe 单次解析，policy 与选路共用不可变快照

- `PBRServe` 对每个请求只调用一次 `ResolveRoute`，生成请求级不可变路由快照；重试、准入与转发消费同一份快照。
- 客户端密钥的车道 policy、成员身份、渠道配置、模型映射、六键与准入配置必须来自同一快照版本，禁止在不同阶段重新读取可变配置。
- `RouteMember` 携带解析后的渠道快照与准入快照；渠道停用、配置错误、映射缺失在该快照中已有确定结论。
- 配置解析是纯函数：只返回“解析值 + 结构化错误”，不得修改缓存、数据库或全局状态。请求路径遇到配置错误必须 fail-closed：该成员不可用、不发上游、不把错误当成“未配置”；全部候选失效时沿用既有 503 契约。管理面写入仍按原契约拒绝非法配置。

### 7. AdmissionOutcome 与请求级 deadline

- 准入结果统一为 `AdmissionOutcome`：`success`、`failure`、`neutral`、`canceled`。
  - `success`：已取得准入并完成一次上游尝试，释放槽位并应用成功反馈；
  - `failure`：已取得准入并完成一次可归因的上游失败，释放槽位并应用失败反馈；
  - `neutral`：未形成上游尝试结论，包括排队期间请求 deadline 到期、waiter 被配置代次变更驱逐、取得准入但发送前即失败；只释放资源，不写成员失败；
  - `canceled`：仅由客户端取消/断开触发；释放资源，不计失败、不冷却、不计熔断。
- 每个请求在入口建立一个**准入绝对 deadline**，只约束排队与 waiter 唤醒；任何单次 `queue_wait_seconds` 都只能缩短、不能延长该 deadline。取得准入后，上游尝试仍按 routing-spec §8 的成员级非流式超时或流式首事件超时执行；提交后不设总超时。
- 准入 deadline 到期不是客户端取消：请求按本地准入超时收尾（`local_throttle`），不得记成 `canceled`；客户端取消与超时在日志、熔断与自适应反馈中严格区分。

### 8. Waiter 必须有身份且可被失效/驱逐

- 每个 waiter 绑定请求上下文、`AdmissionKey`、路由快照 generation 与一次性的结果通道。
- 请求取消、deadline 到期、队列驱逐、配置 generation 变化都会关闭 waiter；迟到回调只能返回“已关闭”，不得重新入队、不得二次释放槽位。
- 队列在有界容量内运行；唤醒与结果投递不得阻塞 State 收口。

### 9. Relay 最早注册清理，流式监督统一终止

- Relay 入口最先注册 State 清理，之后取得的 body、连接、流扫描器、心跳 ticker 与后台任务都归入同一 State。
- 流式心跳、首包等待、正文读取与客户端写出共享一个监督循环。`: PING` 仍不算提交，但心跳写失败必须立即终止本次流，按客户端断开/取消收尾。
- 任意写失败、读失败、上下文取消或 deadline 到期都只能触发一次统一终止；已提交与未提交的故障转移边界不变，不能因清理重复写响应。

### 10. 客户端密钥 lease

- 请求在入口取得客户端密钥的不可变 lease（身份、启用态、车道 policy 与过期时间）；在飞请求不因后续停用、删除或轮换而改变 policy。
- 新请求按最新密钥状态重新鉴权；旧请求的 lease 在 State 收口时幂等释放。密钥对象本身不承担请求生命周期。

### 11. 后台任务使用安全值快照与有界池

- 后台任务启动前复制所需配置与身份为值快照，不持有可变 map、slice、指针或请求上下文。
- 后台执行使用有界 worker 池与有界队列；提交失败、超时、取消和进程关闭都有明确释放路径。禁止每个请求无界创建 goroutine。

## 后果

- 请求资源有了唯一 owner 与幂等收口点，迟到回调、重复 defer、迁移与 Reset 不再互相破坏。
- 健康快照新增 `probe_since`、`probe_lease_until` 与 `config_error`；Reset 响应新增 generation 与失效 lease 计数。
- 出站准入的运行态反馈更准确，排队超时、客户端取消与上游失败不再混写。
- 配置错误从“静默消失”变为可观测的结构化错误，请求路径 fail-closed；坏配置不会被 getter 静默清空。
- 需要补充 `-race`、L2 与 L4 回归，重点覆盖并发收口、租约代次、waiter 驱逐、快照一致性与流式监督。
- **不改变产品边界**：仍是个人自用、单用户、单节点、单二进制 + SQLite 的 LLM 聚合网关；不引入计费/额度、多用户、多节点、第二层网关、自研 TLS 或旧系统迁移。
