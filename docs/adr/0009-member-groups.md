# ADR 0009: 车道成员组（可复用的有序成员子链）

- 状态：已接受（2026-10-25）
- 关联：[ADR 0006](0006-lane-free-member-composition.md)、[ADR 0008](0008-member-stores-selected-model.md)、[routing-spec §1.4](../routing-spec-v1.md)、[api-spec §4.2/§5.2.1](../api-spec-v1.md)

## 背景

多车道常共享几乎相同的成员段：同一批「渠道 × 模型」以相同或相近的顺序出现在多条车道里，
只随流量入口不同而分开建链。此前的模型下，改一处（停用某个成员、调顺序、改六键覆盖）
必须逐车道进编辑器重复操作；漏改一条车道就产生配置漂移，且排障时无法知道
"这几条车道里的同一段"是否真的同步。

## 决策

1. **成员组（member group）是独立实体**：一段**有序成员子链**，成员 = `(渠道, 所选模型)`
   加成员级 `public_alias` / 六键覆盖 / 人工停用开关（能力与散成员完全一致）。
   组名全局唯一。组**不带**六键默认值、不带模式——它是成员的打包，不是小型车道。
2. **车道链元素两态**：车道成员链上允许两种元素——散成员（既有形态）与
   **组引用**（只携带组名与车道级 `enabled` 开关）。链顺序即优先级，组引用在链上
   占一个位置；解析时组引用**展开为连续成员区段**，区段内顺序由组定义，全车道共享。
3. **两层开关**：组实体级 `enabled`（全局）+ 车道引用级 `enabled`（仅本车道）。
   任一层关闭 = 该车道里该组全体成员**按既有「人工停用」口径**跳过（routing-spec §1.2）：
   配置态、留痕 `disabled`、不写冷却、不动熔断、不占探测槽。两层开关之外，
   组内单个成员仍可单独停用。
4. **展开只发生在解析层**（`model.resolveExactRoute`）：`internal/route`、转发管道、
   日志看到的成员链形状不变，冷却/熔断/亲和/探测的成员粒度键（`laneID:memberID`）不变。
   运行态不感知组。
5. **组不排他（2026-10-25 按用户裁决修订）**：组是"复用一段成员链"的快捷方式，
   **不占位、不排他**——同一车道内允许组内成员与散成员重叠（同一 `(渠道, 所选模型)`
   既在组区段里、又以散成员身份出现在链上其他位置，各自是独立成员条目、
   各自有独立运行态），也允许同一组在同一条车道引用多次。唯一性只保留两处：
   **散成员之间**与**组内成员之间**各自 `(渠道, 所选模型)` 唯一
   （重复提交仍 `422 duplicate_member`，但判重范围不再是"展开后全集"）。
6. **manual 点名组成员照旧**：`active_member` 标签仍是 `channel/所选模型` 或别名；
   组任一层被关闭时，manual 点到该组成员 = "无可用、不换人"（routing-spec §2.1）。
7. **删除组 = 级联清理引用**：从所有车道链上移除该组引用；因此链为空的车道整条删除
   （对齐 `cleanup-members` 口径）。不做 409 引用守卫——组是纯内部抽象，删除意图明确。
8. **明确不做**：组嵌套（组套组）、组级 `weighted`/轮询（已删模式不复活，design §7.2）、
   存量车道自动抽组迁移（部署数据，人工编排）。

## 后果

- 车道读写端点的 `members` 数组元素两态（api-spec §4.2），读端点必须完整回传组引用
  （读写闭环通则），编排器草稿与保存载荷随之扩展。
- 新增组 CRUD 端点（api-spec §5.2.1）；导出/导入含 `member_groups`（api-spec §5.6）。
- 解析快照签名必须显式包含组引用与所引组的版本（routing-spec §1.3 契约）。
- 同一渠道映射改动对组内成员同样"配置一次、处处生效"（ADR 0008 不变）。
